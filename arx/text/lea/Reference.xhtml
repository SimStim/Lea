Namespace Tags

lea:author

Purpose: A document without an author is like a letter without a signature. This Lea tag signs it.

Contract: At least one lea:author per file. Any string of Unicode characters as the name. The optional file-as attribute allows filing of authors writing under pseudonyms, following standard library filing rules. Multiple lea:author tags are allowed; the first one carries special weight, as will be shown below. An empty tag passes validation, but Lea will credit the void: keep every lea:author tag filled.

The lea:author tag works hand in hand with lea:title. Lea joins them as “title by author” and derives the name of the compiled xhtml document in the EPUB from it, together with the identifiers under which the manifest and the spine register that file. For lea:link targets, a document answers to both its title alone and its “title by author” form: either variant resolves to the same file. The nav.xhtml and toc.ncx listings show the lea:title content only, and so does the xhtml head title; the lea:author leaves its marks in the EPUB’s document names, the identifiers, and the metadata.

Example:

Frank Herbert]]>

Together with the lea:title from the previous section, this compiles the text into a document named:

and registers it in the manifest and spine under the identifier:

Every author of a text is credited in the content.opf metadata. A second author, say Jack Vance, receives a credit of his own, attached to the very same document:

Jack Vance]]>

The file-as attribute does not alter these credits. It travels to the content.opf, where all authors of all texts are collected, duplicates removed, and written as dc:creator entries. Defining the author as:

Mack Reynolds]]>

compiles to:

Mack
        Reynolds
Reynolds, Dallas McCord
        [Mack Reynolds]]]>

The documents compiled from your text files are marked as Lea’s work: each carries this meta tag in its head:

]]>

Lea never adds herself to the content.opf in any authorial role beyond the generator.

Like lea:title, the lea:author tag polices its content: child tags are stripped, the remaining text is used, and a severe controversy is logged. The flattened string may be acceptable, but editing the file is the recommended fix: it keeps the production log clean.

Attention: A missing lea:author tag is fatal. Lea reports both that at least one author is required and that zero valid author definitions were found; no EPUB will be produced. Both messages name the offending file. Add the tag, or restore it if a typo ate it.

See also: lea:title, lea:target.

lea:block

Purpose: Some fragments appear again and again: colophons, dedications, recurring notices. This tag keeps them written once, in a block file of their own.

Contract: The tag content is the name of a file in Lea’s blocks folder; the optional folder attribute names a subfolder in it. The tag may appear anywhere in a text, as often as needed. The block file holds XML fragments: whatever it contains is imported in place of the lea:block tag.

Blocks are resolved after the text scripts have run their first pass and before their second, so a block may contain lea:script tags, and scripts may generate lea:block tags; both are carried out.

Example: with a file “colophon.xhtml” waiting in the blocks folder,

colophon.xhtml]]>

compiles the file’s content into the text at the tag’s position.

Attention: A block file that cannot be read, or that is empty, is a fatal error: Lea reports the declared block file name and the text containing the declaration, and no EPUB will be produced.

See also: lea:script.

lea:blurb

Purpose: The back-cover copy. A short, tempting text per story, gathered later by a script into a blurbs chapter of your making.

Contract: Defined in a text file, directly under the lea root. The content is free-form text; simple inline markup is kept. No attributes. More than one lea:blurb per text is a severe error: the first definition is used.

Blurbs are not placed automatically. The lea:script named blurbs collects them, and links each blurb’s heading back to its story.

Example:


  Six-legged conspiracies, radio silence from Proxima, and one very
  stubborn postman. Six stories from the 2026 annual edition.
]]>

Attention: A second lea:blurb in the same text is severe: Lea names the blurb she will use and the file it occurs in. The EPUB is produced, but it must not be published.

See also: lea:script.

lea:caption

Purpose: The words beneath the picture. A caption turns an illustration into a statement.

Contract: Lives inside a lea:image tag; that is its only home. The content is free-form text; simple inline markup is kept, and a line break tag is honored. No attributes.

The caption becomes the figure’s caption in the compiled text. It also doubles as the image’s alt text, flattened: markup removed, line breaks and repeated whitespace collapsed to single spaces.

Example:


  Face before the fall.
(Illustration is in the public domain.)
]]>

Attention: More than one lea:caption inside the same lea:image is severe: the first one is used. An image without a caption receives the caption defined in the defaultcaption option, if one is defined.

See also: lea:image, lea:option.

lea:chapter

Purpose: The grand division of a story: a line like “CHAPTER ONE” set above the chapter name. This tag sets both in one move.

Contract: Defined in a text file, directly under the lea root. The content is the chapter name; simple inline markup is kept. Attributes: content-top carries the overline, class-top and class-bottom carry CSS classes for the two headings, and title overrides the label written into the first heading.

The tag compiles into a pair of headings:

The Pyramid of Bottles]]>

compiles to:

CHAPTER ONE

The Pyramid of Bottles
]]>

Without a title attribute, the label defaults to the text’s title, an em-dash, and the chapter name. Without content-top, the upper heading is left empty; define it, or style the empty heading away.

Attention: lea:chapter must be defined directly under the lea root. A chapter tag found nested inside other markup is reported as severe, and omitted from the EPUB entirely.

See also: lea:section, lea:subsection.

lea:collection

Purpose: Binds the book into a series, so readers and bookstores can line the volumes up in order.

Contract: Defined in the ebook definition file, directly under the lea root, at most once. The content is the collection title. Three attributes are required: type, only “series” being supported at the moment; position, the volume’s number in the series; and issn, the ISSN under which the series is registered.

The collection travels into the content.opf as belongs-to-collection metadata with its type and group position, and the ISSN is registered both as dcterms:isPartOf and as an identifier of its own.

Example:

The Pitch Science Fiction]]>

Attention: A declaration that is incomplete, or whose type is not “series,” is ignored silently: the EPUB is compiled as a stand-alone title, without a murmur. Lea believes in series, but she believes in correct data more.

lea:comment

Purpose: A note to yourself, or to the next editor of the file. Lea reads it, nods, and says nothing.

Contract: No attributes; the content is ignored. The tag may appear anywhere, as often as you like, in the ebook definition file and in text files alike.

Comments are carried through compilation and stripped at packaging: they never appear in the EPUB. This makes them a reliable way to fence off regions of a file, such as the metadata block at its top.

lea:contributor

Purpose: Credit where credit is due: editors, translators, cover artists, and everyone else who is an author of nothing and indispensable besides.

Contract: Defined in the ebook definition file, directly under the lea root, as often as needed. The content is the contributor’s name. The roles attribute carries one or more MARC relator codes, separated by spaces; only permitted codes are kept: edt, trl, bkp, bkd, tyg, mrk, pfr, cov, ill, art, and blw.

Each contributor is written to the content.opf as a dc:contributor entry with one role refinement per code. The authors declared with lea:author receive their author role automatically.

Example:

Eduard Pech]]>

Attention: A lea:contributor without at least one permitted role is not included. If no contributor in the ebook carries a valid role, the error is fatal: no EPUB will be produced.

See also: lea:author.

lea:cover

Purpose: The face the book shows the world. This tag commissions the cover page.

Contract: Defined in the ebook definition file, directly under the lea root, at most once. The content is the cover image’s file name, resolved in the images folder. No attributes.

When a cover is declared, Lea compiles a dedicated cover page: it becomes the first document in the reading order, is listed as “Cover” in the navigation documents, and the image itself travels with the EPUB, registered as the cover in the content.opf.

Example:

2025Q4-cover-inside.jpg]]>

Attention: Two things about the cover are fatal: a declared cover file that cannot be found in the file system, and more than one lea:cover definition. In both cases no EPUB will be produced.

See also: lea:image.

lea:date

Purpose: The date the book belongs to. Ebooks are published into time; this tag says when.

Contract: Defined in the ebook definition file, directly under the lea root, exactly once. The content is the issue date. The optional created attribute records the date work on the book began; without it, the issue date is used. The modification date is set by Lea herself, at compile time, and cannot be defined.

Dates are given as YYYY-MM-DD. Lea also accepts natural language: “today” and “yesterday” compile as faithfully as a calendar does.

The three dates travel into the content.opf as dcterms:created, dcterms:modified, and dcterms:issued, with the issue date doubling as dc:date.

Example:

2026-01-01]]>

Attention: A missing, multiple, or unparseable lea:date definition is fatal: no EPUB will be produced.

lea:description

Purpose: The book’s own blurb: what the reader is holding, told to the metadata records of the world.

Contract: Defined in the ebook definition file, directly under the lea root, exactly once. The content is plain text; markup is not kept. No attributes.

The description travels into the content.opf as dc:description.

Example:

The Pitch Science Fiction is a quarterly publication of
  science-fiction stories by various authors, covering diverse themes.
  This is the 2026 annual omnibus edition.]]>

Attention: A missing description is severe: the EPUB is produced, but it must not be published. More than one description is severe as well; the first definition is used.

lea:font

Purpose: Books have voices, and typography is how they sound. This tag embeds a font file into the EPUB.

Contract: Defined in the ebook definition file, directly under the lea root, as often as needed. The content is the font file’s name, resolved in Lea’s fonts folder. No attributes.

Each font is embedded under a normalized name and registered in the manifest. Embedding is half the work: to make the font speak, reference it from your stylesheet with a @font-face rule.

Example:

TeXGyreHeros-Regular.otf]]>

See also: lea:stylesheet.

lea:image

Purpose: Illustrations. Lea wraps the picture, names it, and gives it its caption.

Contract: Defined in a text file or in the ebook definition file, directly under the lea root. The source attribute carries the image file’s name and is mandatory; the optional folder attribute names a subfolder of the images folder, defaulting to the configured images subfolder. An optional lea:caption child carries the caption.

In a text, the tag compiles into a figure:


  Face before the fall.
]]>

compiles to:


  
  
]]>

Every image defined anywhere in the ebook is collected, normalized, and embedded into the EPUB. Images defined in the ebook definition file are embedded without being placed in a text; they wait there for a script or a stylesheet to point at them.

Attention: Three things can rouse Lea’s temper. An image without a source attribute is fatal. A misplaced lea:image is severe and omitted from the EPUB entirely. More than one caption is severe; the first is used. The option include-images, set to “no,” spares her all of it: images are then omitted entirely.

See also: lea:caption, lea:option.

lea:isbn

Purpose: The number the book trade knows you by. Lea takes ISBNs seriously: she checks the checksum.

Contract: Defined in the ebook definition file, directly under the lea root. The content is the ISBN; ISBN-13 is expected, with or without hyphens and spaces, which Lea removes before validating. No attributes.

A valid ISBN becomes the unique identifier of the EPUB: it travels into the content.opf as dc:identifier with its type refinement, and the whole package hangs its identity on it.

Example:

978-3-9823160-0-3]]>

Attention: An ISBN that fails the checksum is severe, and so is more than one lea:isbn definition; in the latter case the first valid ISBN is used. The EPUB is produced, but it must not be published.

lea:language

Purpose: The tongue the book speaks.

Contract: Defined in the ebook definition file, directly under the lea root. The content is the language code, such as en or et. No attributes.

The language travels into the content.opf as dc:language. It also reaches into Lea’s scripts: the author-biography script appends the language code to the file names it looks up when the book is not in English.

Example:

en]]>

Attention: A missing language is severe: the EPUB is produced, but it must not be published.

lea:link

Purpose: Cross-references are the soul of non-fiction. This tag turns a name into a link, within the EPUB or beyond it.

Contract: The tag content names the destination and serves as the visible link text in one. A to attribute decouples the two: it names the destination, and the content stays the visible link text, markup included. Destination names are case-insensitive. No other attributes.

Lea resolves every lea:link against the link targets available in the ebook. Every document answers to its lea:title alone and to its “title by author” form; every lea:target answers to its content (see the next section). A link to a document points at that document; a link to a lea:target additionally jumps to the anchor’s position. If the destination is an external URL, Lea skips the lookup and the link points to the wide world outside the EPUB; add check-urls to the command to have those URLs verified at compile time. A link to an undefined target is fatal: Lea reports the file name and dumps the surrounding markup, and no EPUB will be produced.

Example:

Dune]]>

links to the document compiled from the text titled “Dune,” authored by Frank Herbert:

Dune]]>

with an empty fragment, pointing at the top of the document. The to attribute decouples destination and label:

the novel]]>

compiles to:

the novel]]>

A destination outside the EPUB is taken as it is:

Logophilia]]>

compiles to:

Logophilia]]>

See also: lea:target.

lea:option

Purpose: Switches and knobs for the compile run. Options change how Lea treats the book, without changing the book.

Contract: Defined in the ebook definition file, directly under the lea root. The content is the option’s name; the value attribute carries its value. A declaration without a value attribute is ignored. Options may appear as often as needed; unknown options are remembered but harmless.

Two options are defined at the moment. include-images, set to “no,” omits images from the EPUB entirely. defaultcaption defines the caption given to images that carry none of their own.

Example:

defaultcaption
include-images]]>

See also: lea:image, lea:caption.

lea:publisher

Purpose: The imprint. The publisher’s name is the second half of the EPUB’s file name, and the contact is the address the specification wants on file.

Contract: Defined in the ebook definition file, directly under the lea root, exactly once. The content is the imprint; the contact attribute carries the publisher’s contact and is mandatory. Its value is free-form text: an email address, a telephone number, or the string of your choosing.

The imprint travels into the content.opf as dc:publisher and dcterms:identifier, the contact as dcterms:contact. Together with the book’s title, the imprint forms the EPUB’s file name.

Example:

Logophilia]]>

Attention: A missing or incomplete lea:publisher definition, be it imprint or contact, is fatal: no EPUB will be produced.

lea:rights

Purpose: Who may do what with the book. The law has a taste for fine print; this tag is where it lives.

Contract: Defined directly under the lea root, in the ebook definition file and in text files alike. The content is free-form text; simple inline markup is kept. No attributes. In the ebook definition file, only the first declaration is used.

The ebook’s rights travel into the content.opf as dc:rights. A text’s rights are gathered by the colophon script, which collects the rights of every text into the back matter; this is how anthologies credit each story separately.

Example:

English translation (C) 2025 by Eduard Pech.
Published by permission of the translator’s cat.]]>

Attention: A missing ebook rights declaration is severe, and so is more than one; the EPUB is produced, but it must not be published.

See also: lea:script.

lea:script

Purpose: Lea’s small built-in programs. A script tag asks her to generate content from the book’s own data: tables of contents, colophons, blurbs, author biographies, images with links.

Contract: The content is the script’s name, case-insensitive. The tag may appear anywhere in a text or in the ebook definition file, as often as needed. Individual scripts read attributes of their own, such as skip, folder, class, heading, to, image, and caption.

The scripts on file: toc, also answering to “table of contents” and “list content,” generates a linked table of contents; toc plain generates a plain, alphabetized one; colophon, also answering to “list rights,” gathers the texts’ rights; blurbs gathers the texts’ blurbs; list authors builds a chapter of author biographies from block files; linked image places an image wrapped in a link; and image, also “locked image,” places an image that is not linked.

Scripts are executed in waves: the ebook definition’s scripts run first; then the texts’ scripts; then blocks are resolved; then the texts’ scripts run again. A script may therefore generate a lea:block, and a block may contain a lea:script.

Example:

toc]]>

Attention: An unknown script name is severe: the script is skipped, its tag omitted from the EPUB, and the offense recorded in the production log.

See also: lea:block.

lea:section

Purpose: The signposts within a text. A section marks a chapter-level division inside a document that carries several of them.

Contract: Defined in a text file, directly under the lea root. The content is the heading; simple inline markup is kept. Attributes: title overrides the label written into the heading, and class carries a CSS class. Without a title attribute, the label defaults to the text’s title, an em-dash, and the section’s content.

The tag compiles into a second-level heading:

Namespace Tags]]>

compiles to:

Namespace Tags]]>

Attention: lea:section must be defined directly under the lea root. A section tag found nested inside other markup is reported as severe, and omitted from the EPUB entirely. The navigation documents list whole documents, not the sections within them; the title attribute is there for reading systems and their users.

See also: lea:chapter, lea:subsection.

lea:stylesheet

Purpose: The book’s wardrobe. A stylesheet defines how everything Lea compiles is dressed.

Contract: Defined in the ebook definition file, directly under the lea root, as often as needed. The content is the stylesheet’s file name, resolved in Lea’s styles folder; subfolders are allowed. No attributes.

Every stylesheet is embedded in the EPUB and linked from the head of every compiled document. Image files referenced from within a stylesheet are collected and embedded along with it: background images travel with their CSS.

Example:

golden.css]]>

See also: lea:font, lea:image.

lea:subfolder

Purpose: For books whose sources live in subfolders, so that several books can share one repository without crowding each other.

Contract: Defined in the ebook definition file, directly under the lea root, as often as needed. The content is the subfolder name; leading and trailing slashes are optional. Without attributes, the subfolder applies to the EPUB output, the text files, and the images alike. The tag attribute narrows it to one of those: epub, text, or images.

Example:

tpsf-27
tpsf-shared]]>

Attention: A tag attribute naming anything but epub, text, or images is severe: the declaration is skipped, and the offense recorded in the production log.

lea:subject

Purpose: What the book is about, in the bookseller’s shorthand. Subjects are how readers find a book they did not know they wanted.

Contract: Defined directly under the lea root, in the ebook definition file and in text files alike, as often as needed. The content is the subject term. No attributes.

All subjects of the ebook and its texts are collected, duplicates removed, sorted alphabetically, and written to the content.opf as dc:subject entries.

Example:

Diplomats -- Fiction
Extraterrestrial beings -- Fiction]]>

Attention: A book without any subject declaration receives a warning: the EPUB is produced, but Lea makes her disappointment known.

lea:subsection

Purpose: The finest division of a text: a heading beneath the sections, for structure that should be felt rather than seen.

Contract: Defined in a text file, directly under the lea root. The content is the heading, given as plain text; markup is not kept. The class attribute carries a CSS class. No other attributes.

The tag compiles into a third-level heading:

The Postman’s Route]]>

compiles to:

The Postman’s Route]]>

Attention: lea:subsection must be defined directly under the lea root. A subsection tag found nested inside other markup is reported as severe, and omitted from the EPUB entirely.

See also: lea:section, lea:chapter.

lea:target

Purpose: Sometimes a link must not land at the top of a document but at an exact spot within it. This tag marks that spot.

Contract: The tag content names the target, case-insensitively. No attributes. The content itself is not rendered: the tag compiles into an invisible anchor at its position. Place it right where the landing should be.

Every lea:target in the ebook is registered under its name, and any lea:link is cross-document. A target name may be claimed once: when two identical lea:target tags are declared, the later declaration wins, and a severe error is logged. A target sharing its name with a document, however, is harmless: it upgrades the document link with a jump to the anchor.

Example:

Paul]]>

A lea:link to it, from any source text in the ebook, e.g.

compiles to:

lea:text

Purpose: The declaration of a single text file, and through its position in the ebook definition file, its place in the reading order.

Contract: Defined in the ebook definition file, directly under the lea root, as often as needed. The content is the text file’s name, resolved in the text folder together with the configured text subfolder. No attributes. The order of the declarations is the order of the book: the cover page is set before them and the navigation document after them, both by Lea.

Example:

about-the-authors.xhtml
operation-haystack.xhtml]]>

Attention: Every text must carry a lea:title and at least one lea:author of its own. A text file that cannot be read, or that is not well-formed XML, is fatal, as is a text without its title or author. Each error names the file at fault.

See also: lea:title, lea:author, lea:subfolder.

lea:title

Purpose: No document is complete without a title. This takes care of that.

Contract: Exactly one lea:title per file. Any string of Unicode characters. No XML tags allowed. The tag takes no attributes; everything it does is defined by its content alone.

lea:title works hard: it serves as a link target and can be referenced by scripts to automatically create a table of contents or to list the document rights in the back matter. It labels the document in nav.xhtml and toc.ncx, which facilitate EPUB navigation, and the manifest and spine entries in content.opf are derived from it. The lea:title in the ebook definition file, combined with the publisher name, becomes the filename of the EPUB file itself.

Example:

Operation Haystack]]>

In a text whose author is defined as “Frank Herbert,” this injects into nav.xhtml:


  Operation Haystack]]>

and into toc.ncx:


  
    Operation Haystack
  
  
]]>

The author is assigned to the document in the content.opf metadata:

Frank Herbert]]>

The manifest block receives the document itself:

]]>

and the spine receives the reading order:

]]>

Inside the compiled document, the string defined in lea:title becomes the xhtml head title:


  Operation Haystack
]]>

The lea:title in the ebook definition file follows the same one-title contract. Defined as “Effortless EPUBs,” it becomes:

Effortless EPUBs]]>

All this from one tag per file, with no attributes. Effortless EPUBs it is!

Attention: The lea:title tag is mandatory. A missing tag is a fatal error, and fatal errors prevent the production of the EPUB file. Multiple lea:title definitions are recoverable: the first definition is used, and a severe error is entered into the production log. Both errors name the file they occurred in; edit it to add a lea:title tag or remove the duplicates.

Child tags inside lea:title are likewise severe: Lea strips the tags, uses the remaining text as the title, and logs the guess. The flattened string may be acceptable, but editing the file is the recommended fix: it keeps the production log clean.

See also: lea:author.
