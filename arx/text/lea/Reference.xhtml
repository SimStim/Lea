Namespace Tags

lea:author

Purpose: A document without an author is like a letter without a signature. This Lea tag signs it.

Contract: At least one lea:author per file. Any string of Unicode characters as the name. The optional file-as attribute allows filing of authors writing under pseudonyms, following standard library filing rules. Multiple lea:author tags are allowed; the first one carries special weight, as will be shown below. An empty tag passes validation, but Lea will credit the void: keep every lea:author tag filled.

The lea:author tag works hand in hand with lea:title. Lea joins them as “title by author” and derives the name of the compiled xhtml document in the EPUB from it, together with the identifiers under which the manifest and the spine register that file. For lea:link targets, a document answers to both its title alone and its “title by author” form: either variant resolves to the same file. The nav.xhtml and toc.ncx listings show the lea:title content only, and so does the xhtml head title; the lea:author leaves its marks in the EPUB’s document names, the identifiers, and the metadata.

Frank Herbert]]>

Every author of a text is credited in the content.opf metadata. A second author, say Jack Vance, receives a credit of his own, attached to the very same document:

The file-as attribute does not alter these credits. It travels to the content.opf, where all authors of all texts are collected, duplicates removed, and written as dc:creator entries. Defining the author as:

Mack Reynolds]]>

compiles to:

        Reynolds
Reynolds, Dallas McCord

The documents compiled from your text files are marked as Lea’s work: each carries this meta tag in its head:

Lea never adds herself to the content.opf in any authorial role beyond the generator.

Like lea:title, the lea:author tag polices its content: child tags are stripped, the remaining text is used, and a severe controversy is logged. The flattened string may be acceptable, but editing the file is the recommended fix: it keeps the production log clean.

Attention: A missing lea:author tag is fatal. Lea reports both that at least one author is required and that zero valid author definitions were found; no EPUB will be produced. Both messages name the offending file. Add the tag, or restore it if a typo ate it.

See also: lea:title, lea:target.

lea:link

Purpose: Cross-references are the soul of non-fiction. This tag turns a name into a link, within the EPUB or beyond it.

Contract: The tag content names the destination and serves as the visible link text in one. A to attribute decouples the two: it names the destination, and the content stays the visible link text, markup included. Destination names are case-insensitive. No other attributes.

Lea resolves every lea:link against the link targets available in the ebook. Every document answers to its lea:title alone and to its “title by author” form; every lea:target answers to its content (see the next section). A link to a document points at that document; a link to a lea:target additionally jumps to the anchor’s position. If the destination is a full URL, Lea skips the lookup and the link points to the wide world outside the EPUB; add check-urls to the command to have those verified at compile time. A link to an undefined target is fatal: Lea reports the file name and dumps the surrounding markup, and no EPUB will be produced.

Example:

Dune]]>

links to the document compiled from the text titled “Dune,” authored by Frank Herbert:

Dune]]>

with an empty fragment, pointing at the top of the document. The to attribute decouples destination and label:

the novel]]>

compiles to:

the novel]]>

A destination outside the EPUB is taken as it is:

Logophilia]]>

compiles to:

Logophilia]]>

See also: lea:target.

lea:target

Purpose: Sometimes a link must not land at the top of a document but at an exact spot within it. This tag marks that spot.

Contract: The tag content names the target, case-insensitively. No attributes. The content itself is not rendered: the tag compiles into an invisible anchor at its position. Place it right where the landing should be.

Every lea:target in the ebook is registered under its name, so any lea:link in any document can link to it. A target name may be claimed once: two lea:target tags sharing one name are severe, the last one compiled wins, and a controversy is logged. A target sharing its name with a document, however, is harmless: it upgrades the document link with a jump to the anchor.

Example:

A lea:link to it, from any document in the ebook, compiles to:

See also: lea:link.

lea:title

Purpose: No document is complete without a title. This takes care of that.

Contract: Exactly one lea:title per file. Any string of Unicode characters. No XML tags allowed. The tag takes no attributes; everything it does is defined by its content alone.

lea:title works hard: it serves as a link target and can be referenced by scripts to automatically create a table of contents or to list the document rights in the back matter. It labels the document in nav.xhtml and toc.ncx, which facilitate EPUB navigation, and the manifest and spine entries in content.opf are derived from it. The lea:title in the ebook definition file, combined with the publisher name, becomes the filename of the EPUB file itself.

Example:

Operation Haystack]]>

In a text whose author is defined as “Frank Herbert,” this injects into nav.xhtml:


  Operation Haystack]]>

and into toc.ncx:


  
    Operation Haystack
  
  
]]>

The author is assigned to the document in the content.opf metadata:

Frank Herbert]]>

The manifest block receives the document itself:

]]>

and the spine receives the reading order:

]]>

Inside the compiled document, the string defined in lea:title becomes the xhtml head title:


  Operation Haystack
]]>

The lea:title in the ebook definition file follows the same one-title contract. Defined as “Effortless EPUBs,” it becomes:

Effortless EPUBs]]>

All this from one tag per file, with no attributes. Effortless EPUBs it is!

Attention: The lea:title tag is mandatory. A missing tag is a fatal error, and fatal errors prevent the production of the EPUB file. Multiple lea:title definitions are recoverable: the first definition is used, and a severe error is entered into the production log. Both errors name the file they occurred in; edit it to add a lea:title tag or remove the duplicates.

Child tags inside lea:title are likewise severe: Lea strips the tags, uses the remaining text as the title, and logs the guess. The flattened string may be acceptable, but editing the file is the recommended fix: it keeps the production log clean.

See also: lea:author.
