Purpose: No document is complete without a title. This takes care of that.

Contract: Exactly one lea:title per file. Any string of Unicode characters. No XML tags allowed. The tag takes no attributes; everything it does is defined by its content alone.

Lea:title works hard: it serves as a link target and can be referenced by scripts to automatically create a table of contents or to list the document rights in the back matter. It labels the text in nav.xhtml and toc.ncx, which facilitate EPUB navigation, and the manifest and spine entries in content.opf are derived from it. The lea:title in the ebook definition file, combined with the publisher name, becomes the filename of the EPUB file itself.

Example:

Operation Haystack]]>

In a text whose author is defined as “Frank Herbert”, this injects into nav.xhtml:


  Operation Haystack]]>

and into toc.ncx:


  
    Operation Haystack
  
  
]]>

The author is assigned to the text in the content.opf metadata:

Frank Herbert]]>

The manifest block receives the file itself:

]]>

and the spine receives the reading order:

]]>

Inside the compiled text document, the string defined in lea:title becomes the xhtml head title:


  Operation Haystack
]]>

Lea:title in the ebook definition file follows the same one-title contract. Defined as “Effortless EPUBs,” it becomes:

Effortless EPUBs]]>

All this from one tag per file, with no attributes. Effortless EPUBs it is!

Attention: The lea:title tag is mandatory. A missing tag is a fatal error, and fatal errors prevent the production of the EPUB file. Multiple lea:title definitions are recoverable: the first definition is used, and a severe error is entered into the production log. Both errors name the file they occurred in; edit it to add a lea:title tag or remove the duplicates.

Child tags inside lea:title are likewise severe: Lea strips the tags, uses the remaining text as the title, and logs the guess. The flattened string may be acceptable, but editing the file is the recommended fix: it keeps the production log clean.
