Namespace Tags lea:author lea:author

Purpose

A document without an author is like a letter without a signature. This Lea tag signs it.

Contract

lea:ttitle

At least one lea:author per file. Any string of Unicode characters as the name. The optional file-as attribute allows filing of authors writing under pseudonyms, following standard library filing rules. Multiple lea:author tags are allowed; the first one carries special weight, as will be shown below. An empty tag passes validation, but Lea will credit the void: keep every lea:author tag filled.

The lea:author tag works hand in hand with lea:title. Lea joins them as “title by author” and derives the name of the compiled xhtml document in the EPUB from it, together with the identifiers under which the manifest and the spine register that file. For lea:link targets, a document answers to both its title alone and its “title by author” form: either variant resolves to the same file. The nav.xhtml and toc.ncx listings show the lea:title content only, and so does the xhtml head title; the lea:author leaves its marks in the EPUB’s document names, the identifiers, and the metadata.

Every author of a text is credited in the content.opf metadata. A second author, say Jack Vance, receives a credit of his own, attached to the very same document:

Lea never adds herself to the content.opf in any authorial role beyond the generator.

Like lea:title, the lea:author tag polices its content: child tags are stripped, the remaining text is used, and a severe controversy is logged. The flattened string may be acceptable, but editing the file is the recommended fix: it keeps the production log clean.

Attention

A missing lea:author tag is fatal. Lea reports both that at least one author is required and that zero valid author definitions were found; no EPUB will be produced. Both messages name the offending file. Add the tag, or restore it if a typo ate it.

lea:title, lea:target.

lea:block lea:block

Purpose

Some fragments appear again and again: colophons, dedications, recurring notices. This tag keeps them written once, in a block file of their own.

Contract

The tag content is the name of a file in Lea’s blocks folder; the optional folder attribute names a subfolder in it. The tag may appear anywhere in a text, as often as needed. The block file holds XML fragments: whatever it contains is imported in place of the lea:block tag.

Blocks are resolved after the text scripts have run their first pass and before their second, so a block may contain lea:script tags, and scripts may generate lea:block tags; both are carried out.

Example

With a file “colophon.xhtml” waiting in the blocks folder,

colophon.xhtml]]>

compiles the file’s content into the text at the tag’s position.

Attention

A block file that cannot be read, or that is empty, is a fatal error: Lea reports the declared block file name and the text containing the declaration, and no EPUB will be produced.

See also

lea:script.

lea:blurb lea:blurb

Purpose

The back-cover copy. A short, tempting text per story, gathered later by a script into a blurbs chapter of your making.

Contract

Defined in a text file, directly under the lea root. The content is free-form text; simple inline markup is kept. No attributes. More than one lea:blurb per text is a severe error: the first definition is used.

Blurbs are not placed automatically. The lea:script named blurbs collects them, and links each blurb’s heading back to its story.

Example

  stubborn postman. Six stories from the 2026 annual edition.
]]>

Attention

A second lea:blurb in the same text is severe: Lea names the blurb she will use and the file it occurs in. The EPUB is produced, but it must not be published.

lea:script.

lea:caption lea:caption

Purpose

The words beneath the picture. A caption turns an illustration into a statement.

Contract

Lives inside a lea:image tag; that is its only home. The content is free-form text; simple inline markup is kept, and a line break tag is honored. No attributes.

The caption becomes the figure’s caption in the compiled text. It also doubles as the image’s alt text, flattened: markup removed, line breaks and repeated whitespace collapsed to single spaces.

Example

]]>

Attention

More than one lea:caption inside the same lea:image is severe: the first one is used. An image without a caption receives the caption defined in the defaultcaption option, if one is defined.

lea:chapter lea:chapter

Purpose

The grand division of a story: a line like “CHAPTER ONE” set above the chapter name. This tag sets both in one move.

Contract

Defined in a text file, directly under the lea root. The content is the chapter name; simple inline markup is kept. Attributes: content-top carries the overline, class-top and class-bottom carry CSS classes for the two headings, and title overrides the label written into the first heading.

The tag compiles into a pair of headings:

The Pyramid of Bottles]]>

compiles to:

CHAPTER ONE

The Pyramid of Bottles
]]>

Without a title attribute, the label defaults to the text’s title, an em-dash, and the chapter name. Without content-top, the upper heading is left empty; define it, or style the empty heading away.

Attention

lea:chapter must be defined directly under the lea root. A chapter tag found nested inside other markup is reported as severe, and omitted from the EPUB entirely.

lea:collection lea:collection

Purpose

Binds the book into a series, so readers and bookstores can line the volumes up in order.

Contract

Defined in the ebook definition file, directly under the lea root, at most once. The content is the collection title. Three attributes are required: type, only “series” being supported at the moment; position, the volume’s number in the series; and issn, the ISSN under which the series is registered.

The collection travels into the content.opf as belongs-to-collection metadata with its type and group position, and the ISSN is registered both as dcterms:isPartOf and as an identifier of its own.

Example

The Pitch Science Fiction]]>

Attention

A declaration that is incomplete, or whose type is not “series,” is ignored silently: the EPUB is compiled as a stand-alone title, without a murmur. Lea believes in series, but she believes in correct data more.

See also

lea:title, lea:date, lea:isbn.

Purpose

A note to yourself, or to the next editor of the file. Lea reads it, nods, and says nothing.

Contract

No attributes; the content is ignored. The tag may appear anywhere, as often as you like, in the ebook definition file and in text files alike.

lea:contributor lea:contributor

Purpose

Credit where credit is due: editors, translators, cover artists, and everyone else who is an author of nothing and indispensable besides.

Contract

Defined in the ebook definition file, directly under the lea root, as often as needed. The content is the contributor’s name. The roles attribute carries one or more MARC relator codes, separated by spaces; only permitted codes are kept: edt, trl, bkp, bkd, tyg, mrk, pfr, cov, ill, art, and blw.

Each contributor is written to the content.opf as a dc:contributor entry with one role refinement per code. The authors declared with lea:author receive their author role automatically.

lea:date lea:date

Purpose

The date the book belongs to. Ebooks are published into time; this tag says when.

Contract

Defined in the ebook definition file, directly under the lea root, exactly once. The content is the issue date. The optional created attribute records the date work on the book began; without it, the issue date is used. The modification date is set by Lea herself, at compile time, and cannot be defined.

Dates are given as YYYY-MM-DD. Lea also accepts natural language: “today” and “yesterday” compile as faithfully as a calendar does.

The three dates travel into the content.opf as dcterms:created, dcterms:modified, and dcterms:issued, with the issue date doubling as dc:date.

Example

2026-01-01]]>

Attention

A missing, multiple, or unparseable lea:date definition is fatal: no EPUB will be produced.

See also

lea:publisher, lea:collection, lea:isbn.

lea:isbn lea:isbn

lea:link lea:link

Purpose

Cross-references are the soul of non-fiction. This tag turns a name into a link, within the EPUB or beyond it.

Contract

The tag content names the destination and serves as the visible link text in one. A to attribute decouples the two: it names the destination, and the content stays the visible link text, markup included. Destination names are case-insensitive. No other attributes.

Lea resolves every lea:link against the link targets available in the ebook. Every document answers to its lea:title alone and to its “title by author” form; every lea:target answers to its content (see the next section). A link to a document points at that document; a link to a lea:target additionally jumps to the anchor’s position. If the destination is an external URL, Lea skips the lookup and the link points to the wide world outside the EPUB; add check-urls to the command to have those URLs verified at compile time. A link to an undefined target is fatal: Lea reports the file name and dumps the surrounding markup, and no EPUB will be produced.

Example

Dune]]>

links to the document compiled from the text titled “Dune,” authored by Frank Herbert:

Dune]]>

with an empty fragment, pointing at the top of the document. The to attribute decouples destination and label:

compiles to:

the novel]]>

A destination outside the EPUB is taken as it is:

compiles to:

Switches and knobs for the compile run. Options change how Lea treats the book, without changing the book.

lea:script lea:script

Purpose

Lea’s small built-in programs. A script tag asks her to generate content from the book’s own data: tables of contents, colophons, blurbs, author biographies, images with links.

Contract

The content is the script’s name, case-insensitive. The tag may appear anywhere in a text or in the ebook definition file, as often as needed. Individual scripts read attributes of their own, such as skip, folder, class, heading, to, image, and caption.

The scripts on file: toc, also answering to “table of contents” and “list content,” generates a linked table of contents; toc plain generates a plain, alphabetized one; colophon, also answering to “list rights,” gathers the texts’ rights; blurbs gathers the texts’ blurbs; list authors builds a chapter of author biographies from block files; linked image places an image wrapped in a link; and image, also “locked image,” places an image that is not linked.

Scripts are executed in waves: the ebook definition’s scripts run first; then the texts’ scripts; then blocks are resolved; then the texts’ scripts run again. A script may therefore generate a lea:block, and a block may contain a lea:script.

Example

toc]]>

Attention

An unknown script name is severe: the script is skipped, its tag omitted from the EPUB, and the offense recorded in the production log.

See also

lea:block.

lea:title lea:title

Purpose

No document is complete without a title. This takes care of that.

The lea:title tag is mandatory. A missing tag is a fatal error, and fatal errors prevent the production of the EPUB file. Scripts Templates Notes

Code examples in this Reference are authored as CDATA sections inside a pre element. That is valid XML, and EPUBCheck accepts it: an XML parser treats a CDATA section as opaque character data. An HTML5 parser does not. It reads <![CDATA[ as a bogus comment ending at the first >, then parses the rest of the example as live markup. A lea: element inside the example therefore triggers “Namespace prefix lea on text is not defined.”

Sigil reveals the difference only after its Mend and Prettify command. Opening the untouched EPUB produces no error; the namespace complaints appear when the editor rewrites the document. EPUBCheck remains silent throughout, because it parses the file as XML.

The compiler removes the discrepancy during packaging. XMLetsGoCrazy::stripLeaDom() replaces every CDATA section inside a pre element with a plain text node before the document is serialised. The serialiser then writes the same characters as entities:

<lea:image source="chapter-01-face.jpg">
  <lea:caption>Face before the fall.</lea:caption>
</lea:image>
]]>

The rendered text is unchanged, and both XML and HTML parsers now see text rather than tags. CDATA outside pre is left alone, and the readable CDATA form survives in the source files.

Do not use script as a substitute. It is an HTML raw-text element, but its content is a data block for machines, not rendered document text; reading systems may suppress or ignore it. Escaped text inside pre is the portable construct for visible code.

Implementation Note

DOMCdataSection must be imported into XMLetsGoCrazy. Without the import, instanceof DOMCdataSection resolves to the current namespace, silently returns false, and the conversion never runs.
